# Entities, Value Objects, and Business Rules

> **What to fill in here:** The building blocks of the domain following the DDD tactical model.
> This document translates domain knowledge (obtained in Event Storming) into code models.

> **Stack note:** The concepts of Entity, Value Object, and Aggregate are language-independent.
> Code examples (classes, object mappings, methods) are written in C# to illustrate the design pattern
> implemented in the project. For core database configurations, refer to `data_model.md` §10.

## Tactical DDD concepts

### Entity
An **Entity** is an object defined by its identity, not its attributes.
Two entities are equal if they have the same ID, even if all their other attributes differ.

✓ Entity: Product (distinct by its UUID, even if name or price matches another product)
✓ Entity: User (distinguished by ID and unique username)
✗ Not an entity: Money (A numeric value of 150.00 is identical to another 150.00 in a single-currency system)

### Value Object (VO)
A **Value Object** is an object defined by its attributes; it has no identity of its own.
It is immutable — if an attribute changes, it is a new VO.

✓ Value Object: Money (contains numeric value, enforces away-from-zero rounding)
✓ Value Object: Quantity (strictly positive integer value)
✓ Value Object: DateRange (used for non-persisted on-demand reading reports)

### Aggregate
An **Aggregate** is a cluster of entities and VOs treated as a unit.
It has an **Aggregate Root** which is the entry point — internal objects can only be
accessed through the root.

Sale (Aggregate Root)
├── SaleItem[] (Internal entity mapped inside the aggregate)
├── Quantity (Value Object embedded)
└── Sale.Total (Calculated dynamically, without table column)

**Golden rule of the Aggregate:** Transactions do not cross aggregate boundaries.
Descontar stock y añadir la línea son una sola operación que orquesta el agregado antes de persistir, protegida por concurrencia optimista (`xmin`).

### Business Rules
**Business Rules** (invariants) are the constraints the domain must always satisfy.
They live in the Aggregate Root and are validated on every operation.

## System entities

### Entity: Product

**Context:** `CatalogContext`

**Description:** Artículo del catálogo que posee nombre, precio, stock, categoría y una clave de imagen opcional, y nada más (DP-03).

**Attributes:**

| Attribute | Type | Description | Required | Rules |
|-----------|------|-------------|---------|-------|
| id | Guid/UUID | Unique identifier | Yes | Generated by application |
| name | string | Product name | Yes | Mapped as `varchar(200)`. Trimmed before saving |
| price | Money | Catlog active price | Yes | Numeric(18,2). Enforces `price > 0` |
| stock | int | Units available | Yes | Integer. Enforces `stock >= 0` via database engine |
| category_id | Guid/UUID | Category reference | Yes | Foreign Key restrict targeting `category.id` |
| image_key | string | Opacity key for images | No | Mapped as `varchar(512)`. NULL if missing |
| deleted_at | DateTimeOffset | Soft delete timestamp | No | Shadow property. Global filter excludes logs |

**Lifecycle / States:**

[ACTIVE] ──(Product.Withdraw / Restock)──▶ [ACTIVE]
│
└─────(Soft Delete T-09)──▶ [LOGICALLY DELETED]

| State | Description | Allowed transitions |
|-------|-------------|---------------------|
| `ACTIVE` | Available in the catalog and open for sale operations | → LOGICALLY DELETED |
| `LOGICALLY DELETED` | Retirado del catálogo de forma lógica. El histórico de venta lo sigue leyendo | Terminal state |

**Invariants (Business rules that MUST ALWAYS hold):**

INV-001: Stock No Negativo
• Rule: stock >= 0 after any transactional operation.
• Violation: Fails loudly via ck_product_stock_non_negative database constraint (ADR-002).
• Implementation: Validated inside Product.Withdraw and checked by PostgreSQL.
INV-002: Catálogo Cerrado (DP-03)
• Rule: El producto solo posee nombre, precio, stock, categoría e imagen.
• Violation: Extended properties (SKU, references, descriptions) are explicitly rejected from code models.

**Code example (C#):**

```csharp
public class Product 
{
    public Guid Id { get; private set; }
    public string Name { get; private set; }
    public int Stock { get; private set; }
    public Guid CategoryId { get; private set; }

    private Product() { } // Mapped by Entity Framework

    public static Product Create(Guid id, string name, int initialStock, Guid categoryId) 
    {
        if (string.IsNullOrWhiteSpace(name))
            throw new DomainException("Product name cannot be empty.");
        
        return new Product { Id = id, Name = name.Trim(), Stock = initialStock, CategoryId = categoryId };
    }

    public void Withdraw(int quantity) 
    {
        if (quantity <= 0)
            throw new DomainException("Quantity to withdraw must be positive.");
        if (Stock - quantity < 0)
            throw new DomainException("Retirar más stock del disponible falla. Regla de proceso.");
        
        Stock -= quantity;
    }
}
```

## System Value Objects

### Value Object: Money

**Description:** Representación monetaria del sistema monomoneda (D-05).

**Attributes:**

| Attribute | Type | Description |
|-----------|------|-------------|
| Amount | decimal | Numeric value mapped as `numeric(18,2)` |

**Validation rules:**

• Currency is implicitly default (Monomoneda architecture).
• Enforces 2 decimal precision using MidpointRounding.AwayFromZero before storage.

**Example (C#):**

```csharp
public record Money 
{
    public decimal Amount { get; init; }

    public Money(decimal amount) 
    {
        if (amount < 0)
            throw new DomainException("Money amount cannot be negative.");
        
        Amount = Math.Round(amount, 2, MidpointRounding.AwayFromZero);
    }
}
```

## System System Aggregates

### Aggregate: Sale

**Aggregate Root:** `Sale`

**Internal entities:**
- `SaleItem` — Representa el renglón de venta. Copia de forma congelada los datos del producto en el instante de la transacción.

**Value Objects:**
- `Money` (Precio unitario congelado), `Quantity` (Cantidad vendidas)

**Aggregate invariants:**

AGGR-INV-001: Al menos una línea para poder confirmarse (Sale.EnsureConfirmable).
AGGR-INV-002: Un producto no se repite dentro de la misma venta (Enforced by IX_sale_item_sale_id_product_id).
AGGR-INV-003: El total de venta no se almacena en tablas; se calcula dinámicamente sumando subtotales (Artículo VII).

**Why do these objects form an aggregate?**
> La línea de venta (`SaleItem`) no tiene identidad propia ni ciclo de vida independiente fuera de su venta. La base de datos asume esta composición pura aplicando una regla física de eliminación en cascada (`ON DELETE CASCADE` vinculada a `sale_id`).

## Domain Services

El sistema delega sus procesos complejos a puertos y objetos de valor en memoria. Las agregaciones analíticas de negocio (como el **Reporte de Ventas**) no se persisten en tablas dedicadas; se calculan bajo demanda directamente en el motor de base de datos a través de un puerto de lectura optimizado por índices compuestos (D-06).
